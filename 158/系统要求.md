# 视频音量调整工具 - 系统要求与 Workaround

## 系统要求

### 必需软件

**完整版本 FFmpeg** (推荐 4.0+，测试使用 7.1.1)

必需的 FFmpeg 滤镜支持:
- `loudnorm` - EBU R128 响度标准化，用于分析 LUFS 值
- `volume` - 音量调整滤镜
- `aformat` - 音频格式转换
- `aresample` - 音频重采样
- `scale`, `fps` - 视频处理（可选）

### Python 环境
- Python 3.7+ (使用了 dataclass)
- 仅使用标准库，无需额外安装 Python 包

## 问题诊断：如何检查 FFmpeg 功能

### 检查 FFmpeg 版本
```bash
ffmpeg -version
```

### 检查滤镜支持
```bash
# 检查所有可用滤镜
ffmpeg -filters

# 检查特定滤镜
ffmpeg -filters | grep loudnorm
ffmpeg -filters | grep volume
```

### 测试 loudnorm 分析
```bash
ffmpeg -i input.mp4 -af "loudnorm=print_format=json" -f null -
```

期望输出应包含 JSON 格式的响度数据：
```json
{
    "input_i" : "-26.77",
    "input_tp" : "-22.67",
    "input_lra" : "0.10",
    ...
}
```

## Workaround 方案

### 场景1：系统 FFmpeg 是精简版（缺少滤镜）

**症状**:
- 错误信息包含 "No such filter"
- loudnorm 不输出 JSON 数据
- `ffmpeg -filters` 不显示 loudnorm/volume

**解决方案**:

**macOS (推荐)**:
```bash
brew install ffmpeg
```

**Ubuntu/Debian**:
```bash
sudo apt-get update
sudo apt-get install ffmpeg
```

**CentOS/RHEL**:
```bash
sudo yum install epel-release
sudo yum install ffmpeg
```

**Windows**:
从 https://ffmpeg.org/download.html 下载完整版，解压后添加到 PATH

**验证**:
```bash
# 确保使用新安装的版本
which ffmpeg
# 应显示: /opt/homebrew/bin/ffmpeg (macOS) 或 /usr/bin/ffmpeg

# 验证滤镜支持
ffmpeg -filters | grep -E "loudnorm|volume"
```

### 场景2：PATH 环境变量问题

**症状**:
- 系统已安装完整 ffmpeg，但脚本仍调用精简版
- `which ffmpeg` 显示错误路径

**解决方案**:

**方法1：设置环境变量**
```bash
# macOS (Homebrew)
export PATH="/opt/homebrew/bin:$PATH"
# 或 Intel Mac
export PATH="/usr/local/bin:$PATH"

# 永久设置 (加到 ~/.zshrc 或 ~/.bashrc)
echo 'export PATH="/opt/homebrew/bin:$PATH"' >> ~/.zshrc
```

**方法2：使用完整路径调用**
修改脚本或在调用时指定 ffmpeg 路径：
```bash
# 直接指定路径
/opt/homebrew/bin/python3 video_volume_adjuster.py -i ./videos

# 或在脚本中设置 PATH
import os
os.environ["PATH"] = "/opt/homebrew/bin:" + os.environ.get("PATH", "")
```

### 场景3：临时文件扩展名问题

**症状**:
- 错误信息: "Unable to choose an output format"
- 临时文件扩展名导致 ffmpeg 无法识别格式

**修复**: 已在代码中修复，使用隐藏文件前缀 `.tmp_` 替代扩展名追加

### 场景4：loudnorm 不输出 JSON

**症状**:
- 使用 `-v error` 时 loudnorm 不输出数据

**原因**: FFmpeg 7.x 中 loudnorm 的输出级别变更，`-v error` 会抑制输出

**修复**: 已在代码中移除 `-v error` 参数，改为同时捕获 stdout 和 stderr

## 常见问题

### Q1: 为什么视频没有被重新编码但还是需要时间处理？

A: 虽然视频流是直接复制（`-c:v copy`），但音频流仍然需要：
1. 解码原始音频
2. 应用 volume 滤镜调整音量
3. 重新编码为 AAC 格式
4. 封装到新容器中

处理速度主要取决于音频编码速度，通常比完整视频重编码快 5-10 倍。

### Q2: 为什么调整后的音量与目标有偏差？

A: 音量调整是线性的 dB 增量，而 LUFS 是感知响度。由于:
- 原始音频的动态范围不同
- 最大增益限制（默认 ±10dB）
- 音频编码的微小损失

通常偏差在 ±2 LUFS 内是正常的。

### Q3: 可以处理其他格式吗？

A: 当前仅支持 MP4 和 MKV 格式。如需支持其他格式，修改 `SUPPORTED_EXTENSIONS` 集合并确保 ffmpeg 支持相应的容器格式。

### Q4: 多线程应该设置多少？

A: 推荐设置为 CPU 核心数。对于小文件（<100MB），由于 IO 开销，加速比可能不明显。对于大文件（>1GB），可以达到接近线性的加速。
